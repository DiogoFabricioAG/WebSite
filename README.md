# Diogo Abregu — portfolio

Personal portfolio built with Astro 6, Tailwind CSS 4, TypeScript and the existing React integration. Static output. The homepage presents software engineering and AI systems as a personal technical archive.

## Local development

Use Node.js 22.12+ (validated here on 22.17.1) and npm. The committed lockfile is `package-lock.json`.

```sh
npm ci
npm run dev
npm run build
npm test
npm run preview
```

Development and preview default to port 4321, choosing the next free port when needed. Stop the dev server before previewing if you want to reuse the same port.

`npm test` requires a fresh `npm run build`. It uses Node's built-in test runner to check generated routes, local links and fragments, search metadata, social images, content safeguards and a client-JavaScript budget. There is no configured lint command. No testing library or new runtime dependency was added.

## Structure and routes

- `src/pages/index.astro`: English homepage composed of existing section components.
- `src/layouts/PortfolioLayout.astro` and `src/styles/portfolio.css`: isolated homepage shell, SEO and responsive design tokens.
- `src/data/portfolio.ts`: typed public profile, project, experience, education and community content.
- `src/data/portfolio-verification.ts`: **unpublished** editorial checks. Do not import into client code, JSON-LD or page markup.
- `src/pages/robots.txt.ts`: generated robots file; sitemap is generated by the existing Astro integration.
- `public/Diogo CV.pdf`: existing résumé download, preserved without edits.
- `public/social-card.svg` and `social-card.png`: matching vector source and 1200 × 630 raster social preview.
- `tests/portfolio.test.mjs`: checks against the static build.

Existing Spanish JSON files and unused legacy detail/form components are retained as reference material. They contain claims pending verification and are not the new homepage's public content source. There was no i18n architecture; the homepage is in English. Connect2 and the bot route have been removed at the owner's request. Translation routes and case studies are P1.

## Design and content decisions

The homepage uses a technical archive direction: a petrol background, mineral paper, copper annotations, a large Archivo variable-font masthead, a project index and dossier-style records. Archivo and IBM Plex Mono are self-hosted WOFF2 files with their OFL licenses in `public/fonts/`; the homepage makes no font requests to third parties.

The cover folder previews each project when its index link receives hover or keyboard focus. Anchors work without JavaScript. Each record offers a compact implementation outline and expandable code references pinned to an inspected commit. All project information remains available in static HTML.

The type scale follows the hero container, including when zoomed. Focus styles, skip navigation and reduced-motion preferences are supported. A short masthead entrance and folder transitions add movement without a blocking intro. Native cross-document transitions are disabled to avoid intermittent browser rejection errors.

The custom cursor, scroll-reveal effects and external contact form are absent. Contact uses the email already present in the public CV.

The production canonical is `https://www.diogoabregu.tech`, matching the observed apex redirect. This only changes generated metadata and discovery files. No hosting, DNS, account settings or production deployment was changed. The old manually copied sitemap was removed to avoid competing with generated output.

The owner-provided redesign MD and current CV are primary editorial sources. Roles, supplied metrics, AWS certification, community membership and professional experience are displayed from those sources. A partial public repository does not replace the owner's description of the wider project. Kromata System is the public project name; Print System remains its codebase name. Implementation references and design directions are labeled separately. Missing URLs and illustrative implementation examples are not invented. See [content restoration](docs/PORTFOLIO_CONTENT_RESTORATION.md) for the source-to-section mapping.

Read [the technical archive design notes](docs/PORTFOLIO_ARCHIVE_DESIGN.md) for the current visual direction and validation, and [the original P0 audit](docs/PORTFOLIO_P0_AUDIT.md) for content evidence and the pending checklist. The supplied [redesign specification](docs/PORTFOLIO_REDESIGN_CODEX.md) remains unchanged.

## Social image

The PNG is a rasterization of `public/social-card.svg`, with no fabricated screenshots or metrics. After editing the SVG, regenerate the PNG at its intrinsic 1200 × 630 dimensions using a browser or SVG rasterizer, and run the build tests. The SVG uses the locally hosted display fonts; wait for those fonts before rasterizing. The PNG uses the same Archivo masthead as the homepage.
